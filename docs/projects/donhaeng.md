## 한 줄 소개

취향만 알려주면 AI가 여행 코스를 짜주는, 큰 글씨·쉬운 조작으로 만든 5060 액티브 시니어 특화 여행 플래닝 앱.

## 문제 정의

- 여행 계획은 정보 검색·동선 구성·시간 배분이 겹친 고비용 작업인데, 기존 여행 앱은 **정보를 나열할 뿐 코스를 대신 짜주지 않는다.**
- 특히 5060 액티브 시니어는 여행 수요는 크지만 작은 글씨·복잡한 필터·다단계 플로우에서 이탈한다. 접근성이 곧 사용 여부를 가르는 사용자층이다.
- → **"버튼 한 번으로 오늘의 코스"** 를 만들되, UI 자체를 시니어 기준으로 다시 설계한다.

## 내 역할

**Flutter 앱 프론트엔드 전담 + Next.js 웹 전담** (앱 69 커밋 / 웹 14 커밋, 두 레포 모두 최다 기여자)

- 온보딩(취향 카드 스와이프·튜토리얼 코치마크)부터 홈·코스 생성·지도·평가·설정까지 전 화면 구현
- 소셜 로그인 3종(Google / Kakao / Naver WebView OAuth) 및 약관 동의 플로우
- AdMob 리워드 광고 + 서버 권위 쿼터 연동
- App Links / Universal Links 기반 코스 공유·저장 딥링크
- 코스 공유 웹페이지(SSR + 동적 OG), 약관·계정 삭제 안내 페이지 전담
- Clean Architecture(data / domain / presentation) 구조 설계, 디자인 토큰 단일 출처(`app_theme.dart`) 운영

## 기술적 도전

1. **시니어 접근성을 "감"이 아니라 기준으로 못 박기**
   본문 최소 16pt, 최소 터치 영역 56dp, 주 버튼 높이 72dp, 색 대비 WCAG AA 4.5:1 — 수치 기준을 정해두지 않으면 화면마다 흔들린다.

2. **AI 코스 생성의 대기 시간**
   코스 생성은 수 초~수십 초가 걸리는 작업이라 로딩 스피너만 돌리면 이탈한다. SSE 스트리밍으로 진행 단계를 흘려보내야 했다.

3. **온보딩 튜토리얼 코치마크가 정작 안내할 버튼을 가림**
   딤 레이어가 화면 전체를 덮어, "이 버튼을 누르세요"라고 안내하는 좋아요·건너뛰기 버튼까지 어두워졌다.

4. **백엔드 스키마 변경으로 회원가입이 422로 전면 실패**
   백엔드가 회원 정보 요청 스키마에서 위치 동의 필드를 삭제하고 만 14세 확인 필드를 필수로 추가했는데 앱이 따라가지 않았다. 서버가 정의되지 않은 필드를 거부하도록 설정돼 있어 조용한 무시가 아니라 가입 자체가 막혔다.

5. **클라이언트에 지도 REST 키가 박혀 있음**
   길찾기(directions) 호출을 앱에서 직접 하면 키가 노출된다.

6. **카카오톡 공유 미리보기(OG)**
   카카오톡 크롤러는 JS를 실행하지 않아, 코스 공유 페이지의 OG 태그가 **초기 HTML에** 있어야 한다.

7. **코스 생성 실패가 성공처럼 보임**
   코스가 비어 돌아오면 하드코딩된 2일치 더미 일정으로 폴백하고 있었다. 사용자는 AI가 코스를 만들어 준 줄 알지만 실제로는 생성이 실패한 상태다.

8. **공유 링크를 다시 누를 때마다 여행이 중복 생성됨**
   공유 딥링크로 코스를 저장할 때 서버는 호출마다 새 여행을 만든다. 사용자가 링크를 두 번 누르면 같은 여행이 두 개 쌓인다.

9. **평가 다이얼로그에서 입력창이 키보드에 가림**
   실기기 스모크(S1)에서 발견. 코멘트를 입력하려는데 정작 그 입력창이 키보드 아래로 숨었다.

## 해결 과정

1. **디자인 토큰 단일 출처화** — 색·폰트 크기·간격·반경을 `lib/core/theme/app_theme.dart`의 `DonghangColors` / `DonghangTextStyles` / `DonghangSpacing` / `DonghangRadius`로 모으고, 화면 코드에서 매직넘버 사용을 금지했다. 시니어 UI 기준을 토큰 값 자체에 반영해 개별 화면이 기준을 어길 여지를 없앴다.

2. **SSE 스트리밍 파싱** — named SSE 이벤트를 파싱해 코스 생성 진행 단계를 로딩 화면에 반영. 온보딩 2단계는 배치를 미리 prefetch해 체감 대기를 줄였다.

3. **코치마크 딤에 구멍 뚫기** — 안내 대상 버튼에 `GlobalKey`를 붙여 첫 프레임 이후 화면 좌표를 측정하고, 딤을 `ColoredBox` → `CustomPaint(_ScrimWithHole)`로 교체해 `Path.combine(difference)`로 해당 사각형만(+6px 여유) 도려냈다. 측정 실패 시엔 구멍 없이 기존 전체 딤으로 폴백해 화면이 깨지지 않게 했고, 탭은 그대로 딤이 흡수해 튜토리얼 게이트는 유지했다.

4. **가입 계약 정합** — `origin/main` 계약을 실측해 삭제된 위치 동의 필드 전송을 제거하고 신규 필수 필드(만 14세 확인)를 추가. 동시에 동의 시트를 법무 정본 순서(만 14세 → 이용약관 → 개인정보 수집·이용)로 재배치하고, "개인정보 처리방침 동의"라는 잘못된 라벨을 "개인정보 수집·이용 동의"로 정정했다 — 처리방침은 게시 문서지 동의 체크 대상이 아니다. GPS·개인위치정보를 수집하지 않으므로 위치정보 동의 항목 자체를 폐지했다.

5. **길찾기 백엔드 프록시 이관** — directions 호출을 백엔드 프록시로 옮겨 클라이언트에서 REST 키를 제거했다.

6. **Firebase Hosting 프레임워크 인지 배포** — 코스 페이지를 요청 시점 SSR로 렌더해 OG 태그가 초기 HTML에 포함되도록 했다. 정적 자산은 CDN, 코스 SSR은 Cloud Run으로 자동 분리. 분석 이벤트는 same-origin 라우트(`POST /api/share/{token}/events`)에서 서버가 백엔드로 프록시해 CORS와 베이스 URL 노출을 함께 막았다.

7. **정리와 회귀 방지** — 참조 0건이던 STT 서비스와 데드 라우트 상수를 제거하고 관련 의존성까지 걷어냈다. Phase1 P0 회귀·계약 테스트를 추가하고 스모크 QA 리포트를 남겼다.

8. **더미 폴백 제거 → 빈/에러 상태 UI** — 하드코딩 더미 일정 폴백을 걷어내고 `CourseEmptyState`로 교체했다. 실패했으면 실패했다고 보여준다.

9. **멱등키(Idempotency Key) 도입** — 공유 저장 요청에 `X-Idempotency-Key: save-shared-{token}`을 실었다. 서버가 키를 `{uid}:{key}`로 스코프하므로, **같은 사용자가 몇 번을 눌러도 같은 `tripId`가 돌아온다.** 함께 응답 파싱을 실제 스키마(`tripId`·`dayCount`·`savedCourseCount`)로 교정하고, 존재하지 않는 `alreadySaved` 필드 의존을 제거했다.

10. **키보드 오버랩 — 타이밍 레이스 해소** — 원인은 Dialog 리포지션의 `AnimatedPadding`(100ms)과 `EditableText` caret 재스크롤 사이의 타이밍 레이스였다. `insetAnimationDuration = Duration.zero`로 뷰포트를 즉시 최종 크기로 확정하니 Flutter 내장 재스크롤이 정상 동작했다. 회귀 위젯 테스트를 함께 추가했다.

## 회고

> 아래는 **커밋 이력에서 뽑은 초안**입니다. 판단과 감정은 본인 언어로 다듬으세요.

**1. 실패를 성공처럼 보이게 하는 폴백은 버그보다 나쁘다**

코스가 비어 돌아올 때 하드코딩된 2일치 더미 일정을 보여주는 폴백이 있었다. 화면은 멀쩡해 보이지만, **사용자는 AI가 자기 취향으로 코스를 짜준 줄 알고 그 일정대로 여행을 간다.** 커밋에 "생성 실패를 성공으로 위장하던 사용자 기만 리스크"라고 적어 두었는데, 지금 봐도 그 표현이 정확하다.
폴백은 보통 "안전장치"라고 부르지만, **무엇으로 폴백하느냐에 따라 안전장치가 아니라 거짓말이 된다.** 빈 상태·에러 상태 UI를 제대로 만드는 게 결국 더 정직하고, 사용자가 다시 시도할 기회도 준다.

**2. 계약은 합의하는 게 아니라 실측하는 것 — 같은 기능을 세 번 고쳤다**

코스 평가 전송 방식을 사흘 만에 세 번 고쳤다.
① 자유 코멘트를 `reason` 필드에 `"CODE1,CODE2 | {comment}"`로 결합해 보냈다(백엔드와 free-text 허용 합의).
② 그런데 **배포된 백엔드는 8종 단일 코드만 엄격 검증해서 422로 거부**했다. 합의는 있었지만 배포된 코드는 달랐다.
③ 백엔드 신계약(`reasons` 배열 + `comment` 별도 필드)에 맞춰 다시 썼다.
회원가입이 422로 막혔던 사건도 원인이 같았다 — 백엔드가 스키마를 바꿨는데 앱이 따라가지 않았다.
**문서와 합의는 배포된 코드와 다를 수 있다.** 그래서 이후로는 계약을 `origin/main`에서 실측하고, 요청 body 키를 계약 테스트로 고정했다. 그리고 코멘트 300자 제한처럼 **클라이언트에서 미리 막아 서버 422 자체를 없애는** 방향으로 바꿨다.

**3. 2년 전과 같은 문제를 다시 만났고, 이번엔 다르게 풀었다**

"방금 만든 여행이 홈으로 돌아와도 보이지 않는다" — AllEat에서 `다이어리 생성 후 홈에서 fetch`, `홈으로 돌아갈 때 업데이트`로 하나씩 막았던 바로 그 문제다.
이번에는 원인을 정확히 짚었다. `myTripsProvider`는 캐시라 무효화 없이는 갱신되지 않는데, 앱 복귀(`resumed`)에서만 무효화하고 있어서 **지도에서 뒤로가기로 홈에 돌아오는 경로**가 빠져 있었다. 게다가 생성 흐름이 `pushReplacement`라 push future를 await하는 방식으로는 복귀 시점을 잡을 수 없었다.
그래서 `RouteObserver`를 등록하고 `HomeScreen`을 `RouteAware`로 만들어 `didPopNext`에서 무효화했다. `PageRoute`로 한정해 광고 시트 같은 모달이 닫힐 때는 재조회하지 않도록 했다.
2년 전에는 **화면마다 갱신 시점을 심어서** 막았고, 지금은 **갱신이 필요한 순간을 한 곳에서 관측**해서 풀었다. 같은 증상을 두 번 만나 보고서야 그게 상태 소유권 문제였다는 걸 알았다.

**4. 접근성 기능이 일반 사용자 경험을 망가뜨릴 때**

저장 완료 스낵바가 사라지지 않는 문제가 있었다. 원인이 예상 밖이었다 — **액션 버튼이 붙은 스낵바는 스크린리더가 켜져 있을 때 Flutter가 의도적으로 무기한 유지한다.** 스크린리더 사용자가 액션을 놓치지 않게 하려는 배려다.
액션 버튼을 제거해 해결했다. 접근성을 위한 동작이 다른 사용자에겐 버그로 보일 수 있다는 것, 그리고 **프레임워크의 "이상한 동작"에는 대개 이유가 있다**는 걸 배웠다.

**5. `.gitignore`가 테스트를 통째로 지우고 있었다**

`.gitignore`에 `test/`가 들어가 있어서, `widget_test.dart` 하나를 빼고 **모든 테스트가 버전 관리 밖에 있었다.** 로컬에서는 통과하는데 저장소에는 없는 상태였다.
PushOfLife에서는 빌드 산출물을 `.gitignore`에 안 넣어서 문제였고, 여기서는 넣지 말아야 할 걸 넣어서 문제였다. **`.gitignore`는 한 줄이 조용히 많은 걸 지운다** — 무시 규칙을 추가할 때 무엇이 함께 사라지는지 확인하는 습관이 필요하다.

**6. 5060을 위한 UI는 "크게 만들기"가 아니었다**

본문 16pt, 터치 영역 56dp, 버튼 높이 72dp, 대비 4.5:1 — 수치를 정해 디자인 토큰에 박아 두는 것까지는 쉬웠다. 정작 어려웠던 건 **오해를 만드는 요소를 없애는 일**이었다.
전문 페이지가 없는 약관 항목에 눌러도 아무 일이 없는 셰브론(`>`)이 그려져 있었고, 끌 수 없는 시트에 드래그 핸들이 달려 있었다. 튜토리얼 코치마크는 정작 안내할 버튼까지 어둡게 덮고 있었다.
전부 **"눌리는 것처럼 보이는데 안 눌리는 것"** 이었다. 디지털에 익숙한 사용자는 한 번 눌러 보고 넘어가지만, 익숙하지 않은 사용자는 거기서 "내가 잘못했나" 하고 멈춘다. 접근성은 크기 기준을 지키는 것으로 시작하지만, 결국 **"보이는 것과 되는 것을 일치시키는 일"** 이라는 걸 실기기 확인을 반복하면서 알게 됐다.
