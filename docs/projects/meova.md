## 한 줄 소개

"영화 뭐 봐?"에서 이름을 딴 MEOVA — 상황과 관계에 맞는 영화를 태그로 빠르게 찾고, 불쾌할 수 있는 장면을 미리 알려주는 커뮤니티형 영화 플랫폼.

## 문제 정의

- 가족·친구·연인과 함께 볼 영화를 고를 때 **"뭐 보지?"에 시간을 다 쓴다.** 정보가 넘치는 시대인데 오히려 고르기가 어렵다.
- 추천받은 영화가 **상황에 안 맞는 경우**가 잦다. 가족 영화라고 해서 틀었는데 노골적이거나 잔인한 장면이 나와 불편했던 경험.
- 기존 영화 플랫폼은 메인에 최신/인기/개인화 추천을 나열할 뿐이라, **"지금 이 자리에 맞는 영화"** 를 찾는 데는 도움이 안 된다.

→ 메인 화면에 검색창을 전면에 두고 **태그로 필터링**하면, 검색 시간을 줄이고 접근성을 높일 수 있지 않을까?

**서비스 목적**: 최소 시간·최소 비용으로 관람할 영화를 추천받는, **검색 기능에 중점을 둔** 웹사이트.

## 핵심 기능

**1. 태그 기반 검색**
관람 상황(누구와, 어떤 분위기)에 맞는 태그로 영화를 필터링한다. 메인 화면에 검색창을 직관적으로 배치해 진입 단계를 없앴다.

**2. 태그 코멘트 — 이 서비스의 차별점**
선정성·폭력성처럼 감정적으로 불쾌할 수 있는 요소를 태그화하고, 각 태그에 시청자가 짧은 코멘트를 남길 수 있다. 다른 사람이 **영화를 보기 전에** 어떤 장면이 있는지 파악할 수 있다. 별점 하나로는 전달되지 않는 정보를 다루는 장치다.

**3. AI 데일리 추천**
ChatGPT가 매일 독창적인 테마 하나를 직접 정하고, MEOVA의 영화 DB를 참조해 그 테마에 맞는 영화 3편을 골라 추천한다.

```python
movies = Movie.objects.all()
movie_list = "\n".join([f"{movie.title}({movie.id}) " for movie in movies])
input_message = request.query_params.get('message',
  '독창적인 컨셉 하나를 정해서 그 컨셉에 맞는 영화 3개를 추천해줘')
prompt = f"{input_message}\n영화 목록:\n{movie_list}"
```

응답 형식을 시스템 프롬프트로 고정해 **지정 테마와 영화 ID를 반환**하도록 했다. ID로 받기 때문에 AI가 DB에 없는 영화를 지어내도 걸러낼 수 있다.

**4. 영화·인물 상세**
줄거리, 감독, 배우, 유저 후기를 제공하고 배우·감독의 출연작까지 탐색할 수 있다.

**5. 마이페이지 — 관람 기록 캘린더**
후기를 남긴 날짜에 그 영화의 포스터가 표시되고, 클릭하면 작성한 후기로 이동한다. 팔로우/팔로워 목록, 좋아요한 영화·배우 목록도 제공한다.

**6. 반응형 웹 · 다크 모드**

**1. AI가 존재하지 않는 영화를 추천하는 문제** *(README 코드로 확인됨)*

ChatGPT에 "독창적인 컨셉 하나를 정해서 그에 맞는 영화 3개를 추천해줘"라고 요청하면, **MEOVA DB에 없는 영화를 자연스럽게 지어내서 반환한다.** 추천은 그럴듯한데 클릭하면 상세 페이지가 없는 상황이 된다. 매일 자동으로 도는 기능이라 사람이 검수할 수도 없었다.

**2~4. 확인 필요 — 실제로 겪은 것을 고르세요**
- **태그 기반 필터링 쿼리** — 다중 태그 조합 검색을 Django ORM으로 어떻게 구성했는지, N+1 문제는 없었는지
- **TMDB 데이터 적재** — 외부 API 데이터를 DB에 동기화하는 과정, 호출 제한 대응 (`:package: dumpdata` 커밋이 있으니 fixture로 관리한 흔적은 있습니다)
- **서버 배포** — 본인이 담당했던 배포에서 막혔던 지점

## 해결 과정

**1. 프롬프트로 응답 형식을 고정하고, 영화를 ID로 받기**

DB의 전체 영화 목록을 `제목(ID)` 형태로 만들어 프롬프트에 함께 넣고, 시스템 메시지로 응답 형식을 강제했다.

```python
movies = Movie.objects.all()
movie_list = "\n".join([f"{movie.title}({movie.id}) " for movie in movies])
prompt = f"{input_message}\n영화 목록:\n{movie_list}"
messages = [
  {"role": "system", "content": (
      "너는 영화 추천을 위한 chatbot이고 한글로 꼭 대답해야 해."
      "응답 형식은 항상 동일해야 하며, 다음 형식을 따라야 합니다:\n\n"
      "\"<테마>\"라는 컨셉으로 영화를 추천해드릴게요:\n\n"
      ...
  )},
]
```

핵심은 **제목이 아니라 ID로 받는 것**이다. ID로 받으면 DB 조회 시점에 없는 영화가 자연히 걸러진다. 프롬프트로 "지어내지 마"라고 부탁하는 대신, **지어내도 시스템이 무사한 구조**를 만든 셈이다.

> ⚠️ 2~4번 도전을 채우실 경우 "문제 → 원인 파악 → 시도 → 결과" 순서로 쓰면 읽기 좋습니다.

## 회고

> 아래는 **커밋 이력과 프로젝트 자료에서 뽑은 초안**입니다. 판단과 감정은 본인 언어로 다듬으세요.

**1. AI에게 부탁하지 말고, 틀려도 되는 구조를 만들 것**

2024년 5월은 LLM을 서비스에 붙이는 게 아직 낯설던 때였다. 처음에는 프롬프트를 정교하게 다듬어 "DB에 있는 영화만 추천해"라고 설득하려 했지만, **부탁으로는 보장되지 않는다.** 영화를 ID로 받게 하니 문제 자체가 사라졌다.
AI를 쓸 때 중요한 건 프롬프트를 잘 쓰는 게 아니라, **AI가 틀렸을 때 시스템이 어떻게 되는가**를 먼저 설계하는 것이라는 걸 이 프로젝트에서 배웠다.

**2. 커밋 메시지는 미래의 나에게 쓰는 것**

이 회고를 쓰려고 2년 전 커밋을 열었더니 `:art:`, `:memo:`, `:tada:` 뿐이었다. 무엇을 왜 고쳤는지 하나도 알 수 없었다. 반면 최근 동행 프로젝트의 커밋에는 "백엔드가 2026-07-04에 요청 스키마를 바꿨는데 앱이 따라가지 않아 회원가입이 422로 실패하는 상태였다"처럼 **왜 그 변경이 필요했는지**가 남아 있다.
MEOVA(`:art:`) → SSAFY 팀 프로젝트(`fix: 수정.....`) → 동행(Conventional Commits + 본문에 근거 서술)으로 이어진 변화는 의식적으로 만든 것이다. **기록은 협업을 위해서만이 아니라 미래의 나를 위해 남긴다**는 걸 늦게 알았다.

**3. 태그 코멘트 — 별점이 담지 못하는 정보**

"가족 영화라고 해서 틀었는데 불편한 장면이 나왔다"는 아주 구체적인 불편에서 출발한 기능이다. 평점 8.5점은 그 영화에 어떤 장면이 있는지 알려주지 않는다. **선정성·폭력성을 태그로 만들고 거기에 코멘트를 달게 한 것**은, 점수 하나로 뭉뚱그리던 정보를 쪼갠 시도였다.
기능을 정할 때 "무엇을 보여줄까"보다 **"사용자가 무엇을 몰라서 곤란한가"** 를 먼저 묻게 된 출발점이다.
