# 제출용 포트폴리오 (PDF)

지원할 때 실제로 내는 물건입니다. 웹 사이트는 이 PDF의 **뒷받침**이지 대체물이 아닙니다.

## 역할 분담

| | 역할 | 분량 |
|---|---|---|
| **PDF** (이 폴더) | 실제 제출물. 회사별로 강조를 바꾼 발췌본 | A4 8~10장 |
| **웹** (`cadetbluee.github.io`) | 전체 아카이브. 스크린샷·트러블슈팅 전문 | 제한 없음 |
| **원본** (`docs/projects/*.md`) | 단일 출처. 여기서 꺼내 쓴다 | 제한 없음 |

PDF 앞에 웹 주소 한 줄, 각 프로젝트 끝에 상세 링크. 이러면 PDF는 짧게 유지하면서 깊이는 웹이 받아줍니다.

## 프리셋

매번 새로 쓰지 말고 아래 중 가까운 걸 복사해서 고칩니다.

| 파일 | 대상 | 프로젝트 순서 |
|---|---|---|
| [01-mobile-app.md](01-mobile-app.md) | 모바일 앱 (Flutter · RN · Android) | 동행(앱) → PushOfLife → AllEat |
| [02-fullstack.md](02-fullstack.md) | 풀스택 · 스타트업 | 동행(앱+웹+배포) → MEOVA → PushOfLife |

웹 프론트엔드 전용 프리셋이 필요해지면 02를 복사해 동행의 웹 파트와 Flea:ON을 앞세우면 됩니다.

## 분량 기준 (관행)

- **이력서**: 1~2장 (별도 문서)
- **포트폴리오**: 신입·주니어 기준 **10장 내외 (8~12장)** — 주력 프로젝트 3개 각 2~3장 + 나머지 요약
- 위 두 프리셋은 이 기준에 맞춰 A4 9~10장 분량으로 작성되어 있습니다

**바꾸는 건 순서와 강조뿐입니다.** 사실 관계는 `docs/projects/*.md`에서 그대로 가져오고, 새로 지어내지 않습니다.

동행은 세 프리셋 모두에 들어가되 앞세우는 내용이 다릅니다.

| 프리셋 | 동행에서 강조할 것 |
|---|---|
| 모바일 | Riverpod 상태 관리, 딥링크, 시니어 접근성, 스토어 배포 |
| 웹 | Next.js SSR·동적 OG, 계층 분리, 멱등키 |
| 풀스택 | 앱+웹 1인 전담, 백엔드 계약 정합, 배포까지 |

## 분량 원칙

- **A4 10장을 넘기지 않습니다.** 넘으면 프로젝트를 빼는 게 아니라 **깊이를 줄일 프로젝트를 정합니다.**
- 주력 프로젝트 3개는 각 2~3장, 나머지는 3~4줄 요약.
- 회고는 PDF에 길게 넣지 않습니다. **면접 답변용으로 `docs/projects/*.md`에 남겨두고**, PDF에는 1~2줄만.

## PDF로 만드는 법

가장 빠른 순서대로:

1. **노션** — md를 붙여넣고 `내보내기 → PDF`. 서식이 무난하게 나오고 한글 폰트 문제가 없습니다. 처음엔 이걸 권합니다.
2. **VS Code + Markdown PDF 확장** — 파일 그대로 변환. git 원본과 결과물이 1:1이라 관리가 쉽습니다.
3. **Pandoc** — 통제력은 가장 높지만 한글 폰트 지정이 번거롭습니다.

> **자동화하지 마세요.** 회사별 강조는 문장을 다시 쓰는 일이라 파이프라인을 짜도 이득이 거의 없고 유지보수만 늘어납니다.

## 제출 전 점검

- [ ] 링크가 전부 살아 있는가 (특히 GitHub 비공개 저장소 링크를 넣지 않았는가)
- [ ] 회사가 요구한 분량·형식을 지켰는가
- [ ] 숫자에 근거가 있는가 — **측정하지 않은 수치는 넣지 않습니다**
- [ ] 맞춤법 (`docs/projects/` 원본에 오타가 몇 개 있습니다. 아래 참고)
